How do I know my coding agent's tests are any good?

Break the code the agent changed, on purpose, one small break at a time, and rerun its tests. If the tests still pass after a break, they would not have caught that bug. This is called mutation testing.

Why "all tests pass" is not enough

An agent that writes the code and its tests can write tests that pass no matter what the code does: a test that checks a function runs but not what it returns, or one that only covers the easy case. Coverage does not show this either, because a line can run in a test without any test checking its result.

A real example

On cc's own repo, an agent wrote 211 lines of tests for a folder refresh. All of them passed. Breaking the changed code 4 ways, the tests caught 3. The fourth break, a reverted path, got through: no test covered it (commit 90e4a54c). Score: 3 / (3 + 1) = 75%.

Doing it by hand

  1. Make sure the tests pass as they are.
  2. Change one line the agent wrote: flip a < to <=, a true to false, or drop a call.
  3. Run the tests. A failure means the break was caught. All passing means it was missed.
  4. Undo the change and repeat for the next line.

Open-source mutation tools automate this: StrykerJS for JavaScript and TypeScript, mutmut for Python. Both can run on a whole codebase or be scoped to some files.

When a break is missed

Give the agent the missed break: the file, the line, and what was changed. Ask for a test that fails on that break and passes on the real code. Then run the check again.

Doing it with Proof

Proof comes with Carbon Copy Pro (cc Pro), the one paid add-on for cc, A$19 a month and not on sale yet. It only breaks the lines in the current change, so it fits the moment an agent says it is done.

  • It checks the tests pass first, and stops if they do not.
  • In a temporary copy of the repo, it breaks one changed line at a time: a comparison, a boolean, a return value, a boundary moved by one, a dropped call. At most 40 breaks a run by default.
  • Each break is CAUGHT, MISSED or INVALID (the tests could not load). A break that makes the tests hang counts as caught.
  • The score is caught / (caught + missed). It returns one markdown block for the pull request, with each missed break.
  • Your files are never edited. Proof calls no model.

At launch it supports JavaScript, TypeScript and Python changes, with node --test and pytest. Agents call it as MCP tools: proof_mutate, proof_diff, proof_report.
