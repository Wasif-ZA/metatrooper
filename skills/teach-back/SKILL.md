Use only when the user asks to be taught or tested - "teach me", "quiz me", "prep me for my presentation/oral/review", "I need to be able to defend this". A plain "explain this" or "help me understand" gets a direct explanation, not a quiz.

# teach-back

Understanding is checked, not assumed. The user must be able to say each piece back.

## 1. Map the pieces

List the 5 to 10 ideas the user must hold, in dependency order. Start from what they already
know; ask one question to find that if unsure.

## 2. For each piece

1. **Plain statement**: one idea, common words, two or three sentences.
2. **Worked example**: real numbers or real code from their work, traced step by step.
3. **A picture** when it helps: a small diagram of the flow or the data.
4. **Question**: ask them to explain it back or predict an output. Multiple choice for facts,
   open questions for reasons.
5. **Wrong answer**: correct it, show where the reasoning slipped, then ask a similar but
   different question. Move on only after a right answer.

## 3. Defence practice

For work they must defend: ask the questions a reviewer or marker would ask, hardest last. Time
their answers if the real event is timed. Keep a list of the questions they missed and drill
only those at the end.

## Output

If they want it to keep, one self-contained HTML page: the pieces with examples and diagrams, a
quiz section that marks answers, and the missed-questions list. Readable on a phone.
