First comment

I built cc because I ran three coding agents in three terminals and kept losing track of which one was waiting on me. I also kept pasting screenshots back and forth so an agent could see what it built.

cc puts each agent in a terminal it owns and shows you which one needs you. It runs the official CLIs you install and sign in to yourself, such as Claude Code, Codex and Gemini. It never signs in for you and never reads their login tokens. cc is not affiliated with Anthropic, OpenAI or Google.

What works today:

- The wall. Every agent is a live terminal tile. When one asks a question or waits for a permission, its tile turns orange and moves to the big slot.
- Terminals that survive. A background service owns them, so closing or crashing the window does not stop the agents. When the core starts again, it resumes the live sessions, at most 3 at a time.
- An editor around the terminals. Files an agent changed are marked. A comment on a line of a diff goes to that agent as your next message.
- Browser use. Agents drive browser panes inside the window. Password fields, send-like buttons and the first input on a new site stop for your approval.
- Computer use on Windows. Agents act only on windows you give them, with their own visible cursor. Ctrl+Alt+Q pauses all agent input.

The limits. It is Windows only. There is no installer, so you run it from a clone with Node 24.16 or newer. It is pre-release (0.1.0). There is no sandbox for agents' code yet. The repo and the troop command still use the old name, MetaTrooper.

It is local only: no account and no telemetry. The core is AGPL-3.0.

I built cc to run CLI coding agents in terminals that outlive the window. The core is a background service that owns each terminal. You drive it from a CLI.

[FILL IN if posting: the AI-code disclosure that Rule 4 asks for.]

From a clone, `troop` means `node core/cli.ts`:

    troop start                                   # start the core in the background
    troop ping                                    # check it is up
    troop launch claude --project <path> --prompt "<text>"
    troop launch codex --worktree <branch>        # agent in its own git worktree
    troop sessions [--all]                        # list sessions
    troop owners [path]                           # which session owns each changed file
    troop stop

Add --json to any command for one line of JSON.

- When the core starts again, it resumes the live sessions, at most 3 at a time, with each engine's own resume flag.
- Other tools can drive the core over a named pipe (\\.\pipe\metatrooper) with JSON-RPC. No TCP port.

Article

---
title: I lost track of which coding agent was waiting on me, so I built cc
published: false
description: An IDE for running CLI coding agents side by side on Windows. Pre-release, install from source.
tags: opensource, ai, windows, productivity
---

I ran three coding agents in three terminals. That part worked. The trouble was me.

One agent would stop to ask a question. Its terminal sat behind the other two. I did not see it until I went looking. Meanwhile the other two kept going, and I kept switching windows to check on them.

There was a second problem. When an agent built something visual, it could not see the result. So I took screenshots and pasted them back in, over and over.

Terminal tabs were not made for this. So I built cc: an IDE built around your coding agents.

## The idea

cc puts every agent in a terminal it owns and shows you which one needs you. Around them sits an editor, so you can read and change what they wrote without leaving the window.

I wanted three things:

1. See every agent at once.
2. Have the agent that needs me come to me.
3. Keep the agents running if I close the window.

Everything else grew from those.

## The wall

The wall is the centre of cc. Every agent is a live terminal tile.

When an agent asks a question or waits for a permission, its tile turns orange and moves to the big slot. You do not scan tabs to find it. It comes to you.

It also does not steal your keys. If you were just typing in the big tile, it waits 3 seconds before it moves anything. Finished agents fold to one-line bars.

Each tile says `working`, `waiting for you`, `done` or `exited`. Claude Code reports this through its hooks, and Codex through its notify setting. Other engines show a simpler status taken from their process.

The wall keys use Alt, so a focused terminal keeps every Ctrl key. Alt+arrow moves between tiles. Alt+J jumps to the session that has waited longest. Ctrl+K searches sessions, commands and the text in every live terminal.

## Terminals that survive

A background service, the core, owns the terminals. The window is only a view onto them.

Close or crash the window and every agent keeps working. When the core starts again, it resumes the sessions that were live, at most 3 at a time, with each engine's own resume flag. The wall comes back in the same layout.

## An editor around the agents

Agents write code, so I need to read it without switching apps. The IDE screen has a file tree, tabs, a code editor, search, source control, Problems and a terminal.

Files an agent changed carry a mark. You can open each one as a diff. A comment on a line of a diff goes to that agent as your next message, with the file and line range. That one feature replaced a lot of copying and pasting for me.

## Letting agents see and act

This was the screenshot problem. In cc, agents can drive browser panes inside the window through an MCP server. There is no remote debugging port and no browser extension.

Giving an agent a browser needs guard rails. Typing into a password field, typing text that looks like a credential, and clicking a control named like Send, Submit, Pay, Delete or Publish all stop at an approval card. The first input on a new site asks first too. Only the window can approve, never an agent.

On Windows, agents can also act on app windows you give them. You pick Give window on the agent's tile. Each agent has its own visible cursor, and your real pointer never moves. Ctrl+Alt+Q pauses all agent input, browser and desktop, at once.

## Privacy

The core and the window make no network connection of their own. Your agents talk to their own vendors, as they do outside cc. There is no account and no telemetry.

cc runs the official CLIs you install and sign in to yourself. It never signs in for you and never reads their login tokens. cc is not affiliated with Anthropic, OpenAI or Google.

## The honest limits

- **Windows only.** It was tested on Windows 11.
- **Install from source.** There is no installer yet.
- **Pre-release.** This is version 0.1.0. Some IDE parts are marked "Not built yet" in the UI.
- **No sandbox for agents' code yet.** Agents and the commands they run use your machine with your permissions. The ask mode and approvals are the guard rails.
- **The old name is still around.** The repo, the `troop` command and the `~/.metatrooper/` folder still say MetaTrooper.

## Try it

You need Windows 10 or 11, Node 24.16 or newer, and at least one agent CLI installed and signed in: `claude`, `codex`, `gemini` or `agy`.

```bash
git clone https://github.com/Wasif-ZA/metatrooper
cd metatrooper/core && npm ci
cd ../workbench && npm ci
cd ..
node core/cli.ts start
node core/cli.ts ping
cd workbench && npm run dev
```

Two things happen on first run. Launching Claude Code from the window installs cc's hooks into `~/.claude/settings.json`, and `node core/cli.ts hooks uninstall` takes them out again. The core keeps its state in `~/.metatrooper/troop.db`.

If the wall gets in your way, or an install step fails, open an issue: https://github.com/Wasif-ZA/metatrooper

Release note

# cc v0.1.0 (pre-release)

The first public pre-release of cc: an IDE built around your coding agents.

cc runs Claude Code, Codex and other CLI agents side by side, each in a terminal that keeps going. One place tells you who needs you. Agents can drive a browser and your Windows apps, and anything risky stops for you first.

**Windows only. Install from source. Local only: no account, no telemetry.**

cc is not affiliated with or endorsed by Anthropic, OpenAI or Google.

## Highlights

- **The wall.** Every agent is a live terminal tile. The one waiting for you turns orange and moves to the big slot. Wall keys use Alt, so a focused terminal keeps every Ctrl key.
- **Terminals that survive.** A background service owns the terminals. Close or crash the window and every agent keeps working. When the core starts again, it resumes live sessions, at most 3 at a time.
- **The IDE.** File tree, tabs, editor, search, source control, Problems and a terminal. Files an agent changed are marked. A comment on a line of a diff goes to that agent as your next message.
- **Browser use.** Agents drive browser panes in the window. Password fields, credential-looking text, send-like buttons and new sites stop at an approval card.
- **Computer use (Windows).** Agents act only on windows you give them, through UI Automation, with their own visible cursor. Ctrl+Alt+Q pauses all agent input.
- **Public API.** Other tools drive the core over a named pipe with JSON-RPC.

## Requirements

- Windows 10 or 11 (tested on Windows 11).
- Node 24.16 or newer (tested on 24.18).
- At least one agent CLI installed and signed in: `claude`, `codex`, `gemini` or `agy`.
- A network connection for the first run.

## Install from source

There is no installer yet.

```bash
git clone https://github.com/Wasif-ZA/metatrooper
cd metatrooper/core && npm ci
cd ../workbench && npm ci
cd ..
node core/cli.ts start          # starts the core in the background
node core/cli.ts ping           # checks the core is up
node core/cli.ts skills install # optional: copies the bundled agent skills
cd workbench && npm run dev     # opens the window; needs a desktop session
```

## Before you run it

- Launching Claude Code from the window installs cc's hooks into `~/.claude/settings.json`. `node core/cli.ts hooks uninstall` takes them out again and leaves the rest of the file byte for byte.
- The core keeps its state in `~/.metatrooper/troop.db`. A newer core migrates it, after which an older build cannot open it.
- On first run the window asks how agents should start: ask before each tool call (the default) or auto mode in worktrees.
- The repo, the `troop` command, the `~/.metatrooper/` folder and the package names still use the old name MetaTrooper.

## Known limits

- No sandbox for agents' code yet. Agents and the commands they run use your machine with your permissions.
- Grants and approvals do not stop a hostile program running as you.
- The send-button rule is English only.
- Apps without a UI Automation tree give the agent screenshots only.
- Take-over is close to instant, not instant.
- Some IDE parts are not built. The UI marks them "Not built yet".

Full lists: the Known limits section of the README.

## Uninstall

Run `node core/cli.ts hooks uninstall --codex`, stop the core with `node core/cli.ts stop`, and delete the clone. Delete `~/.metatrooper/` too if you want your history gone.
